# Parser benchmarks on November 24, 2026

Release builds ran on Windows 10 x64 with an AMD Ryzen 9 9950X, .NET SDK 11.0.100 and BenchmarkDotNet 0.16.0-preview.2. Each case ran in three separate processes, each with three warm-up iterations and five measurement iterations targeting 250 ms. Percentages compare mean time per uncached header within the same run. Negative values indicate less time. [Reproduction command](../../readme.md#run-the-benchmarks)

## Fixed-size stack buffer for IIS-encoded headers

Headers containing `+` are decoded into a copy with spaces before detection. Up to 512 characters, the copy now lives in a stack buffer with a fixed size of 1 KiB, sliced to the header length. The previous revision (`876111f`) allocated exactly the header length on the stack. Longer headers still rent from `ArrayPool<char>`. The fixed size keeps stack usage independent of the input. The runtime zeroes the whole buffer, so each decoded header took 1.6–2.8 ns longer. Headers without `+` skip this step.

| Header or workload | Previous revision | Fixed-size buffer | Time change | Allocated per parse |
| --- | ---: | ---: | ---: | ---: |
| IIS-encoded Screaming Frog | 71.66 ns | 74.47 ns | +3.9% | 0 B |
| Unknown client with `+` in its URL | 101.59 ns | 104.03 ns | +2.4% | 0 B |
| Applebot | 116.89 ns | 118.48 ns | +1.4% | 0 B |
| Catalog browsers (44) | 235.64 ns | 235.86 ns | +0.1% | 38 B |
| Catalog crawlers (48) | 81.13 ns | 82.05 ns | +1.1% | 0 B |
| Full catalog (96) | 155.83 ns | 156.27 ns | +0.3% | 18 B |
| API snapshot (60) | 199.06 ns | 204.51 ns | +2.7% | 29 B |

A variant that routed the stack buffer and the rented array through one shared `try`/`finally` block took another 4–5 ns per decoded header and was not adopted.

## First parse in a fresh process

Nine fresh .NET 11 processes each timed their first `Parse` call for Chrome on Windows with `Stopwatch` and read `GC.GetAllocatedBytesForCurrentThread` before and after it. The median was 13.43 ms and 193,792 B. The previous revision took 13.48 ms with the same program and allocated the same number of bytes. The program was rewritten for this run, so compare it only with the previous revision above, not with earlier first-parse figures.

## Reproduction

Build the baseline revision in Release for `net11.0` with `-p:AssemblyName=MyCSharp.HttpUserAgentParser.Baseline` and set `BenchmarkBaselineAssembly` to the absolute path of that DLL. Run the first README benchmark command with the filters `"*MixedWorkloadBenchmarks.Parse*" "*HttpUserAgentParserBenchmarks.Parse*Googlebot*" "*HttpUserAgentParserBenchmarks.Parse*OAI-AdsBot*"` for the comparison with main. For the stack buffer comparison, use `876111f` as baseline and the filters `"*MixedWorkloadBenchmarks.Parse*" "*HttpUserAgentParserBenchmarks.Parse*IIS*" "*HttpUserAgentParserBenchmarks.Parse*Applebot*" "*HttpUserAgentParserBenchmarks.Parse*Unknown*"`. The runtime table uses the mixed workload filter without a baseline and with `-f net8.0`, `net9.0` or `net10.0`.
